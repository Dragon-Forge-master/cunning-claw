CUNNING CLAW / VS OPENCLAW

Cunning Claw vs OpenClaw: what is on before you configure anything.

Both are open-source AI agents you run yourself, and both take prompt injection seriously. They differ in shape and in defaults. OpenClaw is a gateway that reaches you across many chat apps, with a sandbox and approvals you switch on. Cunning Claw is one assistant on one computer, with the approval cards on from the first start and, on Linux, a boxed shell that hides your keys.

Cunning Claw's column describes version 0.5.2. OpenClaw's column is taken from its own documentation at docs.openclaw.ai, read on 22 November 2026, and each cell links the page it came from. OpenClaw moves quickly; if a cell has gone stale, open an issue and it will be corrected. OpenClaw is a separate project with no connection to Cunning Claw or Dragon Forge AI.

The short answer

Pick by what you want switched on for you.

CHOOSE OPENCLAW IF

You want to message your agent from Slack, Signal, iMessage, Teams, Matrix or WhatsApp; you are comfortable with Docker and want a container sandbox with no network by default; you want the project with by far the larger body of documentation; or you run several agents and need per-agent policy.

CHOOSE CUNNING CLAW IF

You want one assistant on your own computer that asks before anything consequential without your configuring it; you want your SSH keys and sign-ins hidden from its shell out of the box; you would rather double-click an installer than run a container; or you are not a developer and want the cards explained in plain words.

Cunning Claw is the newer and smaller of the two. It has run on very few machines and has not been independently audited. Weigh that with everything below.

Why defaults are the comparison

A safeguard nobody switched on protects nobody.

Read feature for feature, OpenClaw has more: more sandbox backends, more of its tools inside the sandbox, an allowlist language, an automatic reviewer, per-agent policy. A person who works through its hardening pages ends up with a tighter machine than a stock Cunning Claw, particularly on network egress.

Cunning Claw was built for the person who will not read those pages. The first time it wants to run a command outside the safe list, send a message or publish something, a card appears and waits. On Linux its shell is boxed and your keys are hidden without a line of config. Config can add to the list of refused commands and can never take from it. That is the whole argument: fewer knobs, set to safe.

Neither project claims to have solved prompt injection, and you should distrust any that does. OpenClaw's docs say model choice is a mitigation and hard enforcement is for anything whose potential damage you would not accept on a bad day. Ours say the approval card is the boundary and it only works if you read it.

Straight answers

What people ask when choosing between them.

Is Cunning Claw a secure alternative to OpenClaw?
It is an alternative with safer defaults for one person on one computer: approval cards on from the first start, and on Linux a boxed shell with your keys hidden. "Secure" needs a qualifier. Cunning Claw is new, has run on very few machines, has no sandbox on Windows and has not been independently audited. A carefully hardened OpenClaw can be locked down further than a stock Cunning Claw.
Is Cunning Claw a fork of OpenClaw?
No. It is a separate codebase written by Dragon Forge AI in Cardiff: one TypeScript process with two runtime dependencies, under the MIT licence. The two projects are not affiliated.
Does OpenClaw have a sandbox?
Yes. Its documentation describes a sandbox that is off by default and, once enabled, runs tool execution in a container (Docker by default) with no network unless you allow it. This page links the OpenClaw pages each statement was read from on 22 November 2026.
Which one uses fewer tokens?
On this point they are level. Both avoid sending every tool's schema with every message: Cunning Claw loads connector tools on demand, and OpenClaw's Tool Search defers tool schemas. Cunning Claw's own test with 150 connector tools cut the tool lists sent with a message by three quarters, from about 61,900 tokens to about 15,100; we have not measured OpenClaw.
Can Cunning Claw be used from WhatsApp or Slack like OpenClaw?
Not in the same way. Cunning Claw can read and draft WhatsApp messages for you in its own browser, and connects to Slack as a tool, but the lines you command it from are its own window, Telegram, Discord and its phone app. OpenClaw's purpose is to be reachable from many chat apps.
Which is easier to install for someone who is not a developer?
Cunning Claw has double-click installers for Windows, macOS and Linux and a setup page that walks you through a free key. The installers are not code-signed yet, so Windows and macOS warn you once. We have not tested OpenClaw's installation and make no claim about it.
