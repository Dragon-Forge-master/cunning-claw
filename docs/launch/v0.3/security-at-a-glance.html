Security at a glance

VERSION 0.3 · 622 AUTOMATED TESTS PASSING · 2 RUNTIME DEPENDENCIES · NOT INDEPENDENTLY AUDITED

Cunning Claw is a local agent with real authority on its operator’s machine: a shell, the file system, a signed-in browser, email, WhatsApp, third-party connectors and ssh. It also reads strangers’ text. A model does not separate instructions from data, so the threat is prompt injection, a confused-deputy attack: persuade the agent and it uses the operator’s privileges for you. The design assumes the model will sometimes be fooled, and puts the boundaries that matter in code.

The floor: twelve, checked first

  • rm -rf, any flag order
  • mkfs
  • dd onto a block device
  • Redirection onto a disk
  • The fork bomb
  • shutdown, reboot, poweroff, halt
  • Recursive chmod/chown on /
  • curl … | sh
  • wget … | sh
  • history -c and shred
  • /etc/shadow, /etc/sudoers
  • sudo -S, a piped password

HARD_DENY in src/tools.ts runs before config, the approval gate and the sandbox. Config can add patterns; nothing removes these, and an approved plan cannot clear them.

Approvals

  • Raised for commands off the auto-approve list, every email or chat send, irreversible browser actions, and MCP tools not recognised as reads.
  • Answered in the HUD, or from Telegram or Discord by an allow-listed operator; Discord cards go only to direct messages.
  • Unanswered in three minutes means no. A new message from the operator cancels every pending card.
  • Publishing cards state the resulting visibility.

The sandbox

Linux: bubblewrap. The whole file system is mounted read-only; only the working folder, the temp directory and folders in sandbox.writable are writable, and the agent’s own config, keys and data stay read-only inside those. Fresh minimal /dev; --new-session blocks terminal keystroke injection. The model never chooses a bind path or a flag. Every result begins with a label saying how it ran.

Hidden: ~/.ssh, ~/.gnupg, ~/.aws, ~/.azure, ~/.kube, gcloud and gh config, docker config, .netrc, .git-credentials, the password store, keyrings, everyday browser profiles, and the agent’s own .env, connector sign-ins and Chrome profile. Credential-like and .env-defined variables are stripped from the environment; ssh and GnuPG agent, keyring, D-Bus and X11/Wayland sockets are hidden.

Leaving the box (unsandboxed: true) always raises its own card, even under a plan; with sandbox.mode: "required" it is refused. macOS: sandbox-exec profile, unit-tested, not yet run on a real Mac. Windows: no sandbox, and every result says so.

The injection scanner

Runs on every tool result before it enters history, scoring thirteen signals: override phrases (in six languages), text addressed to an AI, false authority, role and fence spoofing, secret requests, tool bait, image and link exfiltration, data URLs, encoded blobs, and hidden Unicode. Tag characters, variation-selector smuggling, zero-width and bidi controls are removed, and what they spelled is scored. A hit suspends task grants and plan cover for committing steps for the rest of the turn, and rewords every card. Content is flagged, never blocked.

What leaves the machine

HUD and API bind to 127.0.0.1 behind a self-minted token. No telemetry, no account. Leaving: the conversation to the chosen model provider (none with a local model via Ollama), embeddings requests if a cloud provider is set, and messages to enabled phone lines. Speech-to-text is local with whisper.cpp; without it the browser recogniser is used and the HUD says audio goes to the vendor.

KNOWN GAPS, IN PRIORITY ORDER
  1. Boxed commands can still read the operator’s other files and, with network on (the default), send them. Mitigation: sandbox.network: false.
  2. Document converters run outside the sandbox.
  3. No sandbox on Windows.
  4. macOS sandbox untested on hardware.
  5. The scanner is a heuristic in an open file: evadable by design. Its 23 + 23 sample corpus is a regression floor, not a detection rate.
  6. The approval card works only if a person reads it.
